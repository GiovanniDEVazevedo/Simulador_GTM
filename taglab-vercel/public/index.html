Conectar sua implementação

Cada pessoa pode usar seu próprio contêiner. A escolha fica apenas neste navegador; o padrão é GTM-KW59VB3X. Aplicar recarrega a página para evitar duplicação.

GTG precisa de infraestrutura. Este site aceita o caminho first-party do gateway, mas não cria o roteamento no domínio. Configure o GTG em seu domínio/CDN e depois informe o caminho. Não confunda GTG com um contêiner server-side.

Validação real

O monitor comprova o push no dataLayer. Confirme o disparo da tag no Preview do GTM e o recebimento no DebugView do GA4. Um script carregado não comprova entrega de eventos.

Plano de mensuração

No modo GTM: crie uma Google tag com seu G-ID e acionador All Pages. Crie tags de evento GA4 para os eventos abaixo, com acionadores de Evento personalizado. Ative o envio de dados de e-commerce a partir do dataLayer.

page_view, form_start, form_submit, click, scroll e eventos de vídeo também podem vir da medição otimizada. Escolha uma estratégia por evento para evitar duplicação. O GA4 direto usa send_page_view: false, pois este laboratório envia page_view explicitamente.

Checklist de validação

  1. Configure seu GTM ou GA4 na aba Configuração.
  2. Aceite analytics_storage na aba Consentimento.
  3. Abra o Preview do GTM e conecte esta URL.
  4. Faça o funil: produto → carrinho → checkout → entrega → pagamento → compra.
  5. Inspecione event, ecommerce.items, currency, value e transaction_id.
  6. Confira DebugView e a requisição de coleta no Network. Para GTG, confira o domínio first-party.

Variáveis de camada de dados versão 2: ecommerce.items, ecommerce.value, ecommerce.currency, ecommerce.transaction_id, ecommerce.shipping, ecommerce.shipping_tier e ecommerce.payment_type. Para eventos gerais, use as chaves do JSON do monitor. No GTM, passe debug_mode como parâmetro de evento.

O checkout usa itens e totais calculados, limpa ecommerce antes de cada evento e gera transaction_id único. O reembolso usa a última compra.
